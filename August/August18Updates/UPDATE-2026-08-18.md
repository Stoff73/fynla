# Update — the CRUD handler contract, built and then tested to destruction

The day's spec (`August/August17Updates/SPEC-crud-handler-contract.md`) went from
DRAFT to built. CSJ answered the four open questions in §7, the shared mechanism
landed across all nineteen create handlers, and the post-save link was resolved
once on the server for all three clients.

Then CSJ used it, and found five defects in one conversation — four real, one
introduced by that same evening's work. All five are fixed and verified live.
Full write-up: `August/bugs/fynBug18Aug.md`.

---

## What was done

### 1. §7 answered, spec approved

- **§7.1 identity** — normalised name + provider + owner. Balance is explicitly
  NOT identity: it is the field an edit changes. Over-eager name matching is safe
  by construction, because both ambiguous branches write nothing and ask.
- **§7.2** — answered by measurement, not a probe: sixteen of nineteen create
  handlers had no existence check at all.
- **§7.3 link target** — module page, no per-record deep link.
- **§7.4 C5** — deferred; prompt rule for now.

### 2. One recapture guard, nineteen handlers (`b604fdd3b`)

`RecaptureGuard` is now the single mechanism. What it replaced, all measured:

| Was | Handlers |
|---|---|
| No existence check — silent duplicate | 16 |
| `checkForDuplicate` — warned and discarded the user's answer | savings, investments |
| A 60-second skip that dropped the call | protection (kept: it is in-turn LLM double-emission, a different job) |
| `updateOrCreate` — silent overwrite | `create_will` |
| Correct | `handleCreatePension` — extracted, and deleted from the agent |

An architecture test fails if a create handler skips the guard, or names an entity
type the registry does not know. Two defects surfaced while building the per-entity
matrix: a date column compared Carbon against `"2018-05-12"`, and a decimal cast
compared `"45000.00"` against `45000` — both raising a question about a value that
already matched.

### 3. Receipts and vocabulary (`fbcc403c0`, `0de80b11b`)

Five handlers returned an `id` under a key nothing reads — `create_will`,
`update_will`, both power of attorney handlers, `create_what_if_scenario` — so
`HasAiChat` emitted no entity event for any of them. They now return
`entity_type` + `entity_id` + `name`, and an architecture test bites on a handler
that does not. Rule 9 coverage extended to handler `message` strings, which are
printed to the user verbatim; two acronyms that had already shipped were spelled
out.

### 4. The post-save link, resolved once (`647a609dd`)

- `GateRoutes` gains the entity → page map. It already held the one web/mobile
  route table; a second one would have been the Rule 20 failure.
- `entity_updated` and `entity_deleted` now exist, emitted by one loop over one
  map. `entity_created` had been the only entity event in the application.
- The `capture_complete` record row is built in one place instead of four, and
  carries the page.
- **web** dropped its own hardcoded route table (the fourth copy); **`/m`** offers
  the page as a tappable bubble, and none when the server says that page has no
  mobile route; **native** decodes `entity_type`, `entity_id`, `route`, `label` —
  it discarded all four at decode time, so it could not have built a link at all.

### 5. Five live defects (`4ffe24d56`, `1b80b429c`)

Summarised here, detailed in the bug report:

1. A house-deposit goal answered with the prompt-injection refusal (classifier
   matched "house" → property).
2. One missing field reported as a failure, with an apology and no question mark.
3. "Recorded." over a write that never happened — the continuation was inferred
   from punctuation.
4. **An existing £25,000 goal silently overwritten** — the explicit-edit
   permission was scoped to the entity type, not the record. Introduced by item 2
   of this list reaching the other eighteen handlers. Restored from the audit row.
5. The same question asked twice while the user's new request was dropped.
