## Warnings

### 1. Two near-identically named property totals that deliberately return different answers

**Files:** `app/Services/Estate/UndividedShareDiscount.php:138`,
`app/Services/Shared/CrossModuleAssetAggregator.php:236`
**Category:** 6 — inconsistency with existing patterns / naming collision

`propertyTotal()` and `calculatePropertyTotal()` both sum a user's property, and they
**must** return different figures: the first applies the Inheritance Tax undivided-share
discount, the second must stay undiscounted because net worth and the Letter to Spouse
read it.

That is correct behaviour, but the names do not carry the distinction. Calling the wrong
one is a silent tax error in whichever direction the mistake runs, and it is precisely
the shape this session found twice already:

- **two `net_income` keys** — one take-home pay, one the ITA 2007 s23 figure (W-0205)
- **two `getExistingLifeCover()` methods** — one live, one dead (W-0343)

Both cost real investigation time because a grep on the name did not distinguish them.

**Suggested fix:** rename to `inheritanceTaxPropertyTotal()`. One caller
(`IHTCalculationService::projectProperties()`), so the change is small, and the name
then states which of the two questions it answers.
