Option B · What happens to each Slack post?

Nobody has to choose a system first. Post naturally in Slack; the Fynla agent proposes or performs the correct routing.

One consistent interaction
Slack post

Natural language, screenshot, test result, question or decision.

→
Search and classify

Onyx checks Slack, Drive, GitHub and the vault before responding.

→
Propose action

“Create issue”, “record decision”, “update task” or “answer only”.

→
Approve and link

React ✅ or reply “approve”; the agent writes and posts the permanent link.

Canonical routing map

Bug, failure or test observation

Save to: GitHub Issue

Includes reproduction steps, evidence, relevant code/docs, severity, suggested owner and the Slack thread link.

Feature or product work

Save to: GitHub Issue + Project board

Includes user need, acceptance criteria, dependencies, priority and proposed founder assignment.

Technical decision or learning

Save to: Obsidian vault through a GitHub pull request

Keeps architecture decisions, operating rules and durable engineering knowledge reviewable and versioned.

Business, marketing or finance decision

Save to: the relevant Google Shared Drive folder

Uses folder permissions; finance content is not exposed to agents or channels that lack access.

Schedule, milestone or commitment

Save to: GitHub Project and, when appropriate, Google Calendar

Links the delivery item to its owner, due date, supporting decision and Slack thread.

Question or informal discussion

Save to: Slack only

The answer is cited from the corpus. Nothing is duplicated unless the discussion produces a durable decision or action.

Ownership boundary

Fynla owns

  • Onyx deployment, Postgres, search index and files
  • LiteLLM routing, provider keys and cost controls
  • Agent prompts, routing rules and MCP tool definitions in Git
  • All canonical records in Drive, GitHub, Slack and the vault

Agent cannot do silently

  • Merge code or deploy production
  • Delete or publish company information
  • Change permissions or financial records
  • Apply an ambiguous decision without founder confirmation
