Which operating model should we design in detail?

Click an option. My recommendation prioritises almost no learning curve while preserving an exit path.

A

Managed hybrid pilot — recommended

Onyx Cloud handles search and the Slack agent. Fynla owns the canonical sources, LiteLLM model routing, agent configuration and the action gateway. Move Onyx into Fynla hosting later without changing how the team works.

Pros

  • Fastest adoption
  • Founders mainly use Slack
  • Models remain interchangeable
  • Low initial operational burden

Trade-off

  • Onyx temporarily hosts the derived search index
  • Code and vault require a small ingestion bridge
B

Self-host Onyx immediately

Fynla hosts Onyx, its databases, LiteLLM and the action gateway from day one. The founder experience remains Slack-first.

Pros

  • Fynla controls the complete index
  • No managed knowledge-platform dependency
  • Maximum data-location control

Trade-off

  • More setup, monitoring and upgrades
  • Higher CTO burden before the workflow is proven
C

Build around n8n and a separate chat UI

Use n8n for automation, LibreChat or Open WebUI for deep chat, LiteLLM for models and a separate search store.

Pros

  • Highly configurable
  • Many workflow integrations
  • Components are replaceable

Trade-off

  • Several products to learn and maintain
  • More custom RAG and permission work
  • Least integrated founder experience
