What the founders experience

1 · Post normally

Describe an issue, feature, question, decision or schedule in Slack. Screenshots and thread context are included when available.

2 · Grounded response

The agent searches current sources, answers with links and checks for existing issues or decisions before proposing anything new.

3 · Confirm the action

React ✅ or reply “approve”. No special syntax is required. Ambiguous requests stay as proposals.

4 · Permanent record

The write occurs once, is attributed to the founder, and the GitHub/Drive/vault/Calendar link is posted back into the Slack thread.

Safeguards and failure behaviour

Safe automatic behaviour

  • Search, summarize, cite and identify duplicates
  • Classify Slack posts and suggest the right destination
  • Notify #fynla-agents of indexing or configuration failures
  • Fail over between approved model providers through LiteLLM

Always gated or prohibited

  • Creating or changing records requires founder approval
  • Vault changes are pull requests, never direct commits
  • No code merges, production deploys, permission changes or deletions
  • No production customer data or Fyn CoALA memory enters this corpus

Provider unavailable

LiteLLM selects an approved fallback. The Slack workflow and tools do not change.

Source stale or unavailable

The agent states the last successful sync and will not perform a context-dependent write.

Write fails

No success message is posted. The idempotent request can be retried without creating a duplicate.

Server unavailable

Slack, Drive and GitHub continue normally. Monitoring alerts Chris; the stack restores from nightly backup.
