Design Decisions

  • Greyed items stay visible — users see what they're missing
  • Small tier badge on each locked item (Standard or Pro)
  • Tooltip on hover with tier name + upgrade link
  • No click action — item is not a link, cursor is not-allowed
  • Trial users see everything unlocked (full access for 7 days)
  • Preview users see everything unlocked (demo mode)
  • Collapsed sidebar — locked items show lock icon, tooltip on hover

Backend Middleware

  • New CheckFeatureAccess middleware
  • Applied per-route group: ->middleware('feature:standard')
  • Checks user plan tier against required tier
  • Returns 403 { error: 'upgrade_required', required_plan: 'standard' }
  • Trial + preview users bypass (same as CheckSubscription)
  • Tier hierarchy: student < standard < family < pro

3. Architecture Summary

Frontend Changes

SideMenuItem.vue — new locked + requiredPlan props. When locked: renders as <div> (not router-link), applies opacity + cursor-not-allowed, shows tier badge, tooltip on hover.

SideMenu.vue — adds userPlan computed from subscriptionData prop. Each gated item gets :locked="!hasAccess('standard')" and requiredPlan="standard".

Feature map constant — single source of truth in constants/featureGating.js, mapping route paths to minimum tier. Shared by sidebar and router guard.

Backend Changes

CheckFeatureAccess middleware — new file. Takes tier param. Checks user->plan against tier hierarchy.

routes/api.php — wrap gated route groups: ->middleware('feature:standard') for property, liabilities, business, etc. 'feature:pro' for estate, trusts, will, holistic plan.

Kernel.php — register 'feature' => CheckFeatureAccess::class in route middleware.

No DB changes — uses existing subscription.plan field.
