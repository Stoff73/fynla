Section 1: Life Stage Configuration Architecture

The central config that drives the entire stage-adaptive experience

How It Works

A single configuration object defines every aspect of each life stage. All components read from this config — no scattered if/else logic.

lifeStageConfig.js — Config Shape Per Stage
// resources/js/constants/lifeStageConfig.js export const LIFE_STAGES = { university: { id: 'university', label: 'University & Student', ageRange: '18–25', persona: 'student', tagline: 'Build habits that set you up for life', icon: 'graduation-cap', colour: 'violet', // Sidebar: primary items shown, rest in "Explore more" sidebar: { primary: ['dashboard', 'bank-accounts', 'income', 'expenditure', 'goals'], promoted: ['risk-profile', 'savings'], }, // Dashboard: cards shown and their order dashboard: { hero: 'journey-progress', cards: ['budget-tracker', 'savings-goal', 'student-loan', 'actions'], }, // Onboarding: steps for this journey onboarding: { steps: ['personal-info', 'student-loan', 'income', 'expenditure', 'savings', 'goals'], learningMilestones: { /* per-step content */ }, }, // Learning: stage-contextualised content keys learning: { pensionContext: 'auto-enrolment-from-22', savingsContext: 'emergency-fund-basics', debtContext: 'student-loan-not-like-debt', }, }, early_career: { /* John Morgan config... */ }, mid_career: { /* Carters + Alex Chen... */ }, peak: { /* Mitchells config... */ }, retirement: { /* Bennetts config... */ }, };

Backend Mirror

LifeStageService in PHP holds the same config for API responses, determining which dashboard data to aggregate and which learning content to return. Stage is stored on the user model as life_stage (string enum).

Stage Detection

Three ways a stage is set:

  1. Onboarding selection — user picks their stage on the welcome screen
  2. Preview mode — auto-set from persona's preview_persona_id
  3. Profile update — inferred when DOB/marital status changes (with confirmation)
