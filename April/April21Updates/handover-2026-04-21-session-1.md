## Tech debt found this session

- **DB persistence gap (not in FR-M14 scope).** The buffered off-script filter in `OnboardingChatDirector::handleAssetCaptureTurn` operates on the live SSE stream only. `HasAiChat::chat()` still writes the raw unfiltered LLM text to `ai_messages.content` via `AiMessage::create`. A user who closes and re-opens the conversation will see the off-script sentences that were filtered from the stream. Fix would apply the same filter in `HasAiChat::chat()` before the create call. Not urgent — no bad writes happen, but the UX fix is incomplete until this is addressed.
- **Family-member `fill_form` load race.** "My mum is 72" on `asset_capture(family)` (before the family focus was dropped) produced a success ack but no `family_members` row. Same race exists on module-page `fill_form` usage. Session 3 logged it; session 4 removed the entry-point from onboarding but not the underlying race for module-page use.
- **Asset-capture ack can leak non-keyword instruction text.** Seen in browser testing: Fyn's savings ack included "Just list them with provider, balance, and type." — not a question, not a banned keyword, so it rode through. Not a filter breach, but not the "single short sentence" the prompt asks for. Lives inside the P2 follow-up (FR-N variant) if we want it tightened.
