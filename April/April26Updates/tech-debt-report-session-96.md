## Forward-looking note (not actionable now)

When authoring new architecture tests in Sprint 1+, two patterns to choose between:

1. **`arch()` helper** — preferred for class/namespace/structure tests. No Laravel bootstrap needed.
2. **`it()` closure with Laravel paths** — needed when the test does filesystem walks rooted at `app_path()` / `config_path()` / `base_path()`. Requires `uses(Tests\TestCase::class);` at the top of the file. The session-96 fix to `PersonaMachineryAbsentTest.php` is the canonical example.

If a future architecture test in pattern (2) is authored without the `uses()` line, it will pass in the full sweep (bootstrap leakage from prior tests) and fail in `--testsuite=Architecture` or `pest tests/Architecture/`. The Sprint 0 plan §S0.17 acceptance specifies the `--testsuite=Architecture` form, so the failure mode would be a real CI break.
