### S1 — `liabilityIdentityKey` collision risk for un-provider'd liabilities

**File:** `app/Services/Onboarding/AssetCaptureEntityExtractor.php` `liabilityIdentityKey()` + `extractOneLiability()`.
**Category:** Convention Violation.

The extractor populates `liability_name` only when `extractKnownProvider()` finds a known provider in the chunk. For a liability message without a recognised provider (e.g. "I have a loan of £5000"), `liability_name` is empty and the identity key collapses to `liability|<type>|`. Two distinct un-provider'd credit-card liabilities would collide on the dedup key.

Suggested fix: synthesise a stable name from `liability_type + amount_band` when no provider matches, e.g. `personal_loan_5k`. Or accept the collision as a deliberate dedup behaviour for ambiguous adds (the user can disambiguate by including a provider).

Low priority — surfaces only when a user types two same-type un-provider'd liabilities in the same 24h window.
