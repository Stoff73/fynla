### W1 — Dead ref-fallback chain after AiChatPanel refactor

**File:** `resources/js/components/Shared/AiChatPanel.vue`
**Lines:** 745, 806, 1150, 1157, 1182, 1194 (six occurrences)
**Category:** Dead & Redundant Code

After the session-89 collapse of the docked + modal branches into a single shared body inside `AiChatPanelShell`, the unified template uses `ref="messagesContainer"` only — the docked branch's `ref="dockedMessagesContainer"` is gone. The script's six `this.$refs.messagesContainer || this.$refs.dockedMessagesContainer` fallback expressions now always resolve to the left side and the `||` branch is unreachable.

```js
const container = this.$refs.messagesContainer || this.$refs.dockedMessagesContainer;
```

**Suggested fix:** Drop the `|| this.$refs.dockedMessagesContainer` from all six lines:

```js
const container = this.$refs.messagesContainer;
```

It's harmless at runtime (right side of `||` is `undefined` → no-op) but actively misleads future readers into believing two ref names are still in play. The comment in `scrollToLastUserMessage` already refers to `messagesContainer` only.

## Suggestions

### S1 — Stale `.bg-raspberry-600` selector in user-bubble querySelector

**File:** `resources/js/components/Shared/AiChatPanel.vue`
**Lines:** 747, 1160
**Category:** Dead & Redundant Code

`scrollToLastUserMessage` and one other helper hunt for user bubbles via:

```js
const userBubbles = container.querySelectorAll('.bg-raspberry-500, .bg-raspberry-600');
```

`messageClass()` now returns `bg-raspberry-500` for every user bubble (the unified post-refactor styling). The `.bg-raspberry-600` half of the selector matches only the streaming cursor element at line 238 (`bg-raspberry-600 animate-pulse`), which is a 1.5×4 px sliver inside the assistant bubble — not a user bubble. Matching it would skew the scroll target, though in practice the cursor only exists during streaming and is normally hidden by the time scroll runs.

**Suggested fix:** Tighten to the canonical class:

```js
const userBubbles = container.querySelectorAll('.bg-raspberry-500');
```

If a future change moves user bubbles back to `-600`, the test suite or a manual scroll regression will surface it; better to fail fast than to silently grab the cursor.

### S2 — Modal-mode UX shift: suggestions panel now collapsed by default

**File:** `resources/js/components/Shared/AiChatPanel.vue`
**Line:** 543 (data) + ~270-310 (template)
**Category:** Inconsistency with Existing Patterns

Pre-refactor, the floating modal layout rendered suggested prompts as inline buttons in the empty state (lines 150-163 of the old template) — visible immediately on first open. Post-refactor, both layouts use docked's pattern: a collapsible "Suggestions" panel below the message list, with `suggestionsCollapsed: true` as the default. Modal users now have to expand it once before they see the prompts.

This is consistent across both layouts (the goal of the refactor) and matches docked's existing behaviour, so it isn't a regression — but it IS a behaviour change for modal-mode users worth flagging.

**Suggested fix (optional):** If the always-visible-prompts UX matters for floating modal users (mobile primarily), default `suggestionsCollapsed` to `!this.docked` so the panel auto-opens in modal mode and stays collapsed in docked. Alternatively, leave as-is for unified UX and accept the small modal-mode change.
