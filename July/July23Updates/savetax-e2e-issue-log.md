## Issues found

1. **[Low / cosmetic]** `/m` shell requests `https://csjones.co/favicon.ico` (404) — favicon fetched from domain root instead of `/fynla/`. Console error on every `/m` load.
2. **[Low / edge case — product consideration]** Registering via the SaveTax funnel while the browser still holds a previous user's `/m` session token: the registration POST succeeds (PendingRegistration created) but the UI never shows the verify screen — it lands in the PREVIOUS user's dashboard (observed as test user "Penny", token left from prior session). On a shared/previously-used device a new registrant would silently land inside the old account, with their own verification left dangling. Consider: funnel registration success should clear any existing stored token before navigating.

3. **[Medium — FIX]** Mid-onboarding unlock-action suppression defeated by dashboard cache race on first load. Sequence: verify → User created (`onboarding_fyn_step=NULL`) → `/m` dashboard fetch caches `mobile_dashboard_{id}` (5 min TTL) with the 4 "Unlock … advice" items (midWalk=false at that instant) → Fyn campaign turn stamps `step='base_work'` — too late, cache already poisoned. User sees "Unlock investment advice — date of birth required" while Fyn is about to ask exactly that. Fix: bust `mobile_dashboard_{id}` when `onboarding_fyn_step` changes (one place — User observer or the step-write site in AiChatController). Evidence: Priya id=292, step='base_work' in DB while dashboard showed 4 unlock actions; suppression code in `app/Services/Mobile/NextActionsService.php:86` is correct.

   - Evidence: user 292, turns at ~19:25–19:28 server time, ai_messages for conversation (pull transcript in report phase).
